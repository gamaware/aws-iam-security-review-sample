# CLAUDE.md

Sample AWS IAM and security review for Harbor Goods, a FICTIONAL retailer. Public portfolio repository, layout per
the portfolio standard for sample deliverables.

## Layout

- `report/REPORT.md` is the canonical deliverable. `make report` renders `report/REPORT.pdf` with the same pandoc
  image as CI (ADR 0005); commit it with any change to `report/`. No other PDF engine.
- `evidence/` is generated by `make evidence`. Never edit it by hand; `make evidence-check` diffs it.
- `data/synthetic/before/` is insecure on purpose. Never "fix" it; fixes go in `remediation/` and the resulting
  state in `data/synthetic/after/`.
- `scripts/` is Python standard library only; pytest is the only dev dependency. `scripts/test-live.sh` is manual.
- `tests/` covers the checks, the fixtures, policy consistency and report-to-evidence consistency.

## Rules

- Account IDs: AWS documentation examples only (`111122223333` client, `999988887777` partner, `444455556666`).
  No real names, accounts, emails, IPs, keys or employers. `example.com` for domains. No AI mentions. English,
  dateless prose.
- If a fixture or check changes: `make evidence`, review the diff, update `report/` in the same change.
- `make verify` must pass before a commit; `pre-commit run -a` too.
- Checkov is pinned to 3.3.19 in `.pre-commit-config.yaml` and the `Makefile`; bump both together (ADR 0004).
  Pre-commit hooks are pinned by commit SHA with a `# frozen:` comment; actions by full SHA.
- ADRs in `docs/adr/` use the FoSA2 format with a Compliance section.
- Diagrams: draw.io sources plus PNG exports in `docs/diagrams/`, official AWS icons, a key, left-to-right flow.
- Never run anything against AWS except `make test-live`, and only when the maintainer asks.
